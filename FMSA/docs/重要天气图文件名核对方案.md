# 重要天气图：文件名与图面（时次 / 区域）核对方案

> 状态：方案备忘，尚未实现。后续作为独立项目推进，不要求在现有系统内一次性做完。  
> 适用对象：民航「重要天气预报图 / FIXED TIME FORECAST CHART」一类位图（示例为民航气象中心 FL250–630 固定时次图）。  
> 整理日期：2026-09-22

---

## 1. 要解决什么问题

正常情况下，**文件名已经标注了图的区域和时次**。业务需要的不是从零识别一张未知天气图，而是定期做一致性校验：

```
文件名声称：区域 A、时次 T
图面实际：  区域 ?、时次 ?
判定：      是否匹配；不匹配则记为异常
```

典型异常：贴错名、切错区域图、时次写错、文件与内容对不上。

因此这是**闭集核对**，不是开放式「看图说话」。

---

## 2. 图上两类关键信息

| 信息 | 图上形态 | 能否直接当文字读 | 建议技术 |
|------|----------|------------------|----------|
| 预报有效期 | 图例中的印刷体，如 `有效时间（世界协调时）：00 UTC 2026-09-22` / `VALID 00 UTC 22 Sep 2026` | 能 | 裁图例 + OCR + 正则 |
| 图纸区域 | 底图陆地/海岸线轮廓；一般**没有**可用的区域标题 | 不能（即使偶尔有 `40N`、`80E` 等网格字，也小、易与等高线数字混淆，**业务上不依赖**） | 同区域固定底图 → 模板匹配 |

补充：

- 时次按图面 **UTC** 解析，不要按本地时猜测。
- 火山注记里的点坐标（如 `SAKURA-JIMA 31.6N, 130.7E`）只是点位，不能当图幅范围。
- 天气符号（ISOL EMBD CB、急流 FL、锋面）**不是本功能的识别目标**。第一期不做要素抽取。

---

## 3. 总体流水线

```
文件
  ├─ 文件名解析 → claimed_region, claimed_valid_time
  └─ 图像
        ├─ 图例 ROI → OCR → actual_valid_time
        └─ 去天气色 → 陆地/岸线掩膜 → 与各区域模板比分
              → actual_region
                    ↓
              比对：时次是否一致、区域是否一致
                    ↓
              一致 / 异常（含与哪套模板更像，便于审计）
```

时次与区域分开处理，不要整图丢给一个模型。

---

## 4. 时次：OCR

### 4.1 为什么可行

有效期在左下（或固定）图例框，版式相对稳定、字号较大、中英往往同时出现。裁切图例区再识别，比整图 OCR 更稳。

### 4.2 推荐库

| 用途 | 选择 | 说明 |
|------|------|------|
| 首选 | PaddleOCR 3.x / PP-OCRv5 | 中英混排、小字较好 |
| 轻量部署 | RapidOCR（ONNX 跑 PP-OCRv5） | 适合定时批处理 |
| 不建议当主力 | Tesseract、EasyOCR | 短英文、红框、图例小字容易错 |

### 4.3 解析

OCR 全文后用正则抽取，例如：

- `VALID\s+(\d{2})\s+UTC\s+(\d{1,2})\s+(Jan\|Feb\|...)\s+(\d{4})`
- `有效时间.*?(\d{2})\s*UTC\s*(\d{4}-\d{2}-\d{2})`
- 同时出现时以 UTC 日历日互核

输出建议：`actual_valid_time = 2026-09-22T00:00:00Z`（若产品是时段而非单时次，保留起止）。

与文件名中的时次做规范化后再比（去掉分隔符、统一时区、统一 `00`/`0` 填充）。

### 4.4 失败条件

扫描歪斜、分辨率过低、图例被裁切。预处理：纠偏、提高对比度、只送图例 ROI。

## 5. 区域：模板匹配（主方案）

### 5.1 为什么不用「通用地图识别 / 多模态当主判据」

同一区域的**底图轮廓是固定的**，不同时次只是天气叠加工具层在变。这正是模板匹配的适用条件。

相对多模态（GPT-4o、Qwen-VL、Gemini 等）：

| | 模板匹配 | 多模态 |
|--|----------|--------|
| 目标 | 「是不是文件名说的那张底图」 | 「这大概是哪一块」 |
| 稳定性 | 可复现、可设阈值 | 同一张图描述可能漂 |
| 成本 | 本地、适合定期跑 | API/GPU 更贵 |
| 审计 | 可报与各模板的相似度 | 「看起来像东亚」难复核 |
| 精确 bbox | 不需要现场估经纬度 | 估范围不准 |

多模态更适合**没有固定切图、区域集合不明确**的开放识别。本业务区域种类有限、轮廓固定，模板匹配更容易落地。

多模态可留作**无模板新区域、切图异常时的复核**，不作为主路径。

### 5.2 必须比底图，不能比整图

直接拿带天气的整图去和模板比会误报：红色 CB 区、急流、锋面每次都不同。

正确对象：

- 保留：陆地填色、海洋填色、海岸线/国界
- 去掉：红色天气区与红字框、黑色急流、棕色谱面/变高线、标题图例（可先裁掉）

### 5.3 没有官方空白底图时，如何得到模板

只有带标记的历史图即可。思路：同一区域、不同时次，**不变的是岸线，变的是天气**。

#### 推荐：多样本中值（每区 20 张以上更好）

1. **颜色过滤**（不必一次擦干净）  
   按 HSV/RGB 丢掉大红、部分纯黑天气线，保留米色陆地、浅蓝色海。
2. **对齐**  
   同区域切图通常固定，仍可能差几像素或分辨率不同。用陆地掩膜或岸线做 ORB / ECC 配准。
3. **像素中值**

```python
import numpy as np
import cv2

# imgs: 已对齐、已去红的同区域图，shape 一致
stack = np.stack(imgs, axis=0)          # (N, H, W, 3)
basemap = np.median(stack, axis=0).astype(np.uint8)

land = cv2.cvtColor(basemap, cv2.COLOR_BGR2HSV)
mask = cv2.inRange(land, (10, 20, 160), (35, 90, 255))  # 米色阈值需按实图标定
mask = cv2.morphologyEx(mask, cv2.MORPH_CLOSE, np.ones((5, 5), np.uint8))
cv2.imwrite("region_EA_template.png", mask)
```

4. **每个区域人工看一眼**  
   中值后若残着急流或红点，一次性擦掉。区域种类少，属于一次性成本。

得到的不是出版级空白地图，而是**该区域的稳定轮廓签名**，用于核对已经够用。

#### 图很少时（3～5 张）

中值去不干净，退化为单张/少量图的颜色提陆地：

1. 米色 → 陆地，浅蓝色 → 海洋  
2. 红、典型天气黑线丢掉  
3. 形态学闭运算补小缺口  
4. 陆地掩膜当模板  

精度低于多样本中值，但东亚这类轮廓（大陆 + 日韩台）通常仍能和其他标准切图分开。

不要在单张图上做复杂 inpaint「还原完整地图」：岸线容易被修歪。校验要的是可匹配的轮廓，不是能再印刷的底图。

### 5.4 在线核对

待检图走**与生成模板相同的预处理**（去红、提陆地），再和模板比：

- 轮廓/边缘：Canny + `matchTemplate` 或相关
- 掩膜 IoU / SSIM（分辨率一致时简单够用）
- 切图略有缩放时：先用 ORB/SIFT 配准再比

决策（必须和「声称区域」比，也要和其它区域比，避免只知道「不像 A」却发现不了其实是 B）：

```
filename_region = EA
score(EA)   = 0.92
score(WPAC) = 0.41
→ 区域一致

filename_region = EA
score(EA)   = 0.28
score(WPAC) = 0.88
→ 文件名区域与图面不符（更像西太）
```

阈值用历史真值样本标定，输出相似度便于抽检。

## 6. 建议输出

每张图一条记录，例如：

```json
{
  "file": "EA_20260922_00.png",
  "claimed": { "region": "EA", "valid_time": "2026-09-22T00:00:00Z" },
  "actual": {
    "valid_time": "2026-09-22T00:00:00Z",
    "valid_time_raw": "VALID 00 UTC 22 Sep 2026",
    "region": "EA",
    "region_scores": { "EA": 0.92, "WPAC": 0.41 }
  },
  "match": { "time": true, "region": true },
  "anomaly": false
}
```

区域字段用**产品代码**（与文件名约定一致），不要用模型自由生成的「中国周边」这类短语。覆盖经纬范围若需要，在配置里按产品代码写死，不要让算法现场估 bbox。

## 7. 实施阶段（独立项目）

| 阶段 | 内容 | 说明 |
|------|------|------|
| 0 | 约定文件名规则、区域代码表、每区收集历史样张 | 没有样张无法标定颜色和阈值 |
| 1 | 图例 OCR + 时次与文件名比对 | 先把时次核对跑通，价值高、依赖少 |
| 2 | 每区生成陆地模板（中值 + 人工点检） | 一次性 |
| 3 | 待检图预处理 + 多模板打分 + 区域核对 | 定时批处理 |
| 4 | 抽检集上调阈值、补失败 case | 歪斜、低分辨率、图例裁切 |
| 5（可选） | 无模板/低分样本走多模态复核 | 只从区域名单中选，禁止编造经纬度 |

不建议第一期做：CB 要素结构化、锋面识别、精确图幅 bbox、通用「任意天气图认全球区域」。

## 9. 风险与边界

- 新区域上线必须先做模板，否则只能标「未知区域」。  
- 底图改版（投影、切图、陆地填色）后要重建该区模板。  
- 天气符号若大面积盖住岸线，单张掩膜会残缺，多样本中值 + 形态学可缓解；极端情况进人工或低分复核。  
- 文件名解析规则必须先书面固定，否则「声称时次」本身就不稳。  
- 若将来能拿到矢量 PDF / 数字产品，时次与区域应以数字源为准，位图核对降为辅。

---

## 10. 结论（讨论共识）

1. **时次**：图例文字，OCR 可做，作为第一期。  
2. **区域**：同区轮廓固定，**模板匹配是主方案**；多模态不是更准的主路径，只适合开放识别或兜底。  
3. **干净底图**：不依赖官方空白图；用同区域历史「有标记图纸」去天气色、对齐、像素中值，再少量人工清理。  
4. 本能力适合**单独项目**分阶段做，先时次核对，再区域模板。
